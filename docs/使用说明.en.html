What it is

Pecia is a lightweight native Markdown editor for Windows: double-click to run, a single file with no installer, live preview beside your text, and a built-in library of text-processing scripts.

It is a writing and note-taking tool - not an IDE, not a sync service. Your files stay on your own disk; the preview, the scripts and the AI integration all revolve around the document in front of you.

  • Fast to open, fast to preview, low footprint - these three are the judge of every design decision.
  • The preview pane is read-only: click links, double-click images, drag-select to copy - edit text back in the editor.
  • Embedded Lua 5.5 with the PCRE2 regex library (rex.*); the script bar ships with 90+ official text-processing scripts, ready to use.
  • A built-in AI chat panel (its own column in the main window) for polishing, translating and tidying text - or connect Pecia to an external AI via MCP and let it edit the document directly.

What it can do

Editing

  • Multi-tab, draggable editor/preview layout; ratios and window state persist.
  • Line numbers, current-line highlight, long-line ruler, smart CJK-Latin word wrap (never breaks inside a word).
  • Find/replace (regex), go-to-line, undo grouped per operation - one script run = one undo step.
  • Encoding auto-detection (UTF-8/GBK and more) with round-trip saving; Save As can switch encoding and line endings.

Preview

  • Headings/tables/task lists/footnotes/callouts; code blocks, mermaid diagrams and LaTeX math render live.
  • Chunked rendering for large documents - even a 100 MB file scrolls smoothly; the TOC button folds into a collapsible outline.
  • "Preview only" mode: editing locks and search runs inside the rendered text - ideal for a final read-through.

Automation

  • Bottom script bar: every .lua in the install folder script\ appears grouped (subfolder = submenu).
  • View > AI Chat: its own column in the main window, alongside the Markdown preview - both can be open at once with a draggable divider; selected text goes to it via the right-click "Send to AI"; the panel has just Clear and Send.
  • MCP stdio endpoint: external AI clients read/write the current document, run Lua and query the outline (see the ★ section below).

Quick start

  1. Start Pecia.exe, drag a .md file into the window (or Ctrl+O).
  2. Ctrl+Shift+P opens the preview; drag the divider to rebalance.
  3. Ctrl+S saves. Want a scratch pad at boot? Enable "Fixed startup document" in Settings - Pecia then opens Test.txt on launch.
  4. Side panel: a file tree on the left, outline on the right; width is draggable and the panel can hide entirely.
  5. Not your colors? Settings > Theme (5 built-in palettes, custom theme .ini files also supported).
  6. Settings > Options has four pages: Editing (tabs/long-line ruler/search engine/auto-indent/URL detection/paste media - with it on, Ctrl+V turns clipboard images/files into Markdown links; save the document first, and a clipboard that carries text still pastes as text), Exit & Save (autosave/temp cleanup/whitespace trimming/tab expansion), Interface & System (multi-tab/fixed startup document/open .md behavior/new-text documents/associations), AI (API URL, model, API key, context turns - the built-in chat uses exactly this; turns are how much conversation history rides along with each message, default 25, oldest dropped beyond that; the endpoint and model ship pre-filled, and if you clear them the chat says so plainly instead of reporting a network failure). The vertical page rail hugs the left edge, full height, tinted like the menu bar.

Writing scripts

Any .lua in script\ works; a few header comments are metadata:

--!param mode=d,dropdown|dedupe|sort  target=select?
local out = rex.gsub(input, "\\s+", " ")   -- input is the selected text
return out                                  -- the return value replaces the selection
  • --!param declares parameters; a dialog opens automatically before the run (dropdowns/checkboxes/text, multilingual labels).
  • Four API tables: editor (selection/caret), win (dialogs/clipboard), rex (PCRE2 regex), pecia (host operations: open/save/outline/find…).
  • The full manual ships as script\lua_api.txt - written for humans and for AI alike.
Scripts run with your account's full permissions (file I/O, launching programs - all within reach). That is a deliberate trade-off: run only scripts you trust.

★ Put an AI to work through MCP (copy this and go)

You do not need to know the MCP protocol or remember tool names. Send the text below to any MCP-capable AI; it will read the shipped docs, connect to Pecia, do the job by the rules and verify its own results.

Text to copy and send to the AI 
I have a Pecia editor installed at <folder containing Pecia.exe>. It is a lightweight Markdown editor for Windows and exposes MCP tools that let you read and write the current document, run built-in Lua scripts, query the outline and more.

First open the install folder and read these documents carefully; follow their rules exactly:
- docs\使用说明.en.html (overall features)
- docs\MCP接入.md (how to connect to Pecia's MCP, with config snippets)
- script\lua_api.txt (full Lua and host-operation API - read before running any script)

Once connected, tell me which tools you can see and what you plan to do, and wait for my confirmation before acting.

The task I want done: <describe in plain words, as concretely as you can - e.g. "renumber the citation list in the current document and check for orphaned references">.

Also follow these rules: prefer doc.apply_edit for edits (it refuses non-unique anchors - do not work around it); write complex transforms as Lua scripts and run lua.validate first (compile-only; it returns the line number and Lua's own error), then lua.run on the snapshot; run installed scripts with script.run plus params instead of relying on dialogs; after each step verify with doc.get_text before continuing; when a script needs input, pass parameters in script.run's params (modal dialogs stall the single-request MCP endpoint); if the document is read-only or preview-locked you will get perm_denied - that means protection, not failure; do not retry, ask me. A failed tool call is guaranteed to have changed nothing - fix the arguments and call again.
The red <...> placeholders are yours to fill in: the install folder is filled once and reused; the task is whatever you actually want done. Send the rest verbatim. If the AI asks questions first, that is normal - it is confirming the scope.

Why the prompt is shaped this way

  • Stating the doc locations and the read-first rule keeps the AI from inventing APIs or splitting one replacement into ten calls.
  • Asking for a plan before action lets you correct course before any file changes.
  • The perm_denied semantics are explained up front: it is the edit lock protecting your document, not a malfunction.
  • Requiring self-verification makes the "edit, read back, adjust" loop hands-free.

Connection details live in docs\MCP接入.md; for what the connection can do and where it stops, see the next section.

What MCP access can do

Pecia ships a standard MCP stdio endpoint (Pecia.exe --mcp-stdio) with no fixed client. Any client that speaks MCP stdio and can set a command and args field connects.

  • Read: full document or a byte range, state (path/dirty/encoding), outline, search hits, script list.
  • Write: anchor-based replace, snapshot replace, save, open, switch tabs - all scoped to the active tab and subject to the edit lock.
  • Execute: lua.validate compiles without running; lua.run executes on a snapshot (a failed run changes nothing; a successful one is a single undo step); script.run runs installed scripts with parameters. PCRE2 regex (rex.*) and host operations (pecia.*) are all available.
  • UI inspection: script dialogs (parameter prompts, inputs, pickers) are created by the host, so the host publishes their widget tree - ui.inspect reads it, ui.send synthesizes clicks and typing, ui.pixel samples colors off-screen, ui.wait waits for a dialog to appear or vanish. FLTK draws its own widgets, so external accessibility tools cannot see them; this toolset exists mainly for Pecia's own UI regression gates.
  • Drafts land as files: Lua has no console window anymore (m037) - a draft is just text: console.set writes it, console.get reads it back; console.show opens it as an ordinary editor tab, and script.save turns it into a script that appears in the bottom bar.
  • The tool list, lua_api.txt and pecia.ops() all come from one source - what the AI sees is exactly what runs.
Failed tool results guarantee "nothing changed" (isError) - fix the arguments and retry; when the client disconnects, the Pecia window keeps working as usual.

No MCP? Use the built-in View > AI Chat panel (its own column, open alongside the preview): select text and use the right-click Send to AI; the panel has just Clear and Send; API URL / model / key live in Settings > Options. To move a reply into the document, select and copy it - automatic write-back is the MCP side's job.

FAQ

Huge files feel slow?

Very large documents pause visibly on first parse (known design) and then open read-only - choose full editing in the notice.

Math / mermaid not rendering?

First use loads lazily; give it a moment, then Menu > Refresh (Ctrl+R) forces a rebuild.

Remote images missing?

The preview fetches and caches them; offline you get placeholders. Exporting HTML localizes images into the output folder.

Where are settings stored? How do I move machines?

Everything lives in settings.ini beside the exe (recent files, column ratios, shortcuts) - copy that one file and you have migrated.

Do multiple Pecia instances fight over settings?

No. Settings are shared across instances and sync live; the AI chat is a column of the main window - there are no per-instance subprocesses. The Lua console has no window at all anymore (m037): scripts run from the bottom bar, the draft is a text file script.last.txt, and results appear on the status bar.

Does it work offline?

Yes. Editing, preview, scripts and MCP are all offline; only update checks and remote images touch the network.
