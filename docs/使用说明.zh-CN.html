它是什么

Pecia 是一个 Windows 原生的轻量 Markdown 编辑器：双击即开、单文件无安装依赖， 边写边在右侧实时预览，顺带一套内置的文本处理脚本。

它是写作与记录工具，不是 IDE，也不是笔记同步软件。文件就在你自己硬盘上， 预览、脚本、AI 接入都围绕"你眼前这份文档"进行。

  • 打开快、切预览快、占用低——这三条是它一切设计取舍的裁判。
  • 预览区默认只读：点链接、双击图片、拖选复制都可以，改文字请回编辑区。
  • 内置 Lua 5.5 与 PCRE2 正则库（rex.*），脚本栏收录 90 多个官方文本处理脚本，开箱即用。
  • 自带 AI 对话面板（主窗口独立一栏，帮助润色、翻译、整理文本），也可以把 Pecia 接到外部 AI（MCP）让它直接改文档。

适合谁用

你是……Pecia 能给你的
记笔记 / 写文档的人即开即写的 Markdown，大纲侧栏、目录跳转、表格/公式/mermaid 实时预览。
经常处理文本的人去重、加序号、中英混排空格、正则替换……底栏脚本一点，结果直接替换选区。
多语言用户界面 16 种语言即时切换并记忆，含 RTL（阿拉伯语）。
想让 AI 干活的人标准 MCP 接口：AI 能读你的文档、跑脚本、改完自己复验；不配 MCP 也有内置对话面板。
会点 Lua 的人往 script\ 扔个 .lua 就多一个菜单项，参数框自动生成。
Pecia 不联网也能用全功能；只有检查更新、渲染远程图片时才需要网络。Lua 脚本不是沙箱——只运行你信任的脚本。

能做什么

编辑

  • 多标签、分栏拖动的编辑/预览布局，比例与窗口状态都持久化。
  • 行号、当前行标记、长行标尺、中英混排智能换行（不在汉字中间硬断行）。
  • 查找/替换（支持正则）、跳转行、撤销重做按"操作"而非按键计——一次脚本运行 = 一次撤销。
  • 编码自动识别（UTF-8/GBK 等）并按原编码存回；另存为可换编码、换换行符。

预览

  • 标题/表格/任务列表/脚注/高亮块；代码块、mermaid 流程图、LaTeX 公式即时渲染。
  • 大文档分块渲染，百 MB 级文件也不会拖死滚动；目录按钮展开可折叠大纲。
  • 「仅预览」模式：编辑能力锁上，查找直接在渲染文字里做——适合发布前通读。

自动化

  • 底栏脚本菜单：安装目录 script\ 里的 .lua 自动成组（子文件夹 = 子菜单）。
  • 视图 > AI 对话：主窗口里独立的一栏，与 Markdown 预览各占一栏、可同时打开，中间的分隔条可拖；选中文字走右键「发送到 AI」，面板里只有 清除 与 发送。
  • MCP stdio 端点：外部 AI 客户端可直接读写当前文档、运行 Lua、查大纲（见下文 ★ 一节）。

快速上手

  1. 双击 Pecia.exe 启动，把 .md 文件拖进窗口即打开（或 Ctrl+O）。
  2. Ctrl+Shift+P 打开右侧预览；分隔条拖动调整左右比例，工具窗的预览同理。
  3. Ctrl+S 保存。想开机即记：设置里打开「固定启动文档」，之后双击 Pecia 直接进 Test.txt。
  4. 左侧面板：文件树按目录走，大纲按标题跳；面板宽度可拖、可整体隐藏。
  5. 不顺手就换皮肤：设置 > 主题（内置 5 套配色，另支持自定义主题 ini 文件）。
  6. 设置 > 选项 分四页：编辑（制表符/长行标记/搜索引擎/自动缩进/检测网址/粘贴素材——打开后 Ctrl+V 会把剪贴板里的图片/文件落成 Markdown 链接，需先保存文档；剪贴板里有文字时仍按普通粘贴处理）、退出与保存（自动保存/清理临时文件/去空白/Tab 转空格）、界面与系统（多标签/固定启动文档/打开 .md 时/新建文本文档/打开方式）、AI（API URL、模型、API Key、上下文轮数——内置对话用的就是这一份；轮数是每次随消息一起发送的历史对话深度，默认 25，超出截最旧；接口地址与模型名出厂已预填，清空后对话栏会直说「AI 配置错误」，不会报成网络故障）。左侧标签条贴边通高（顶到标题栏、下接按钮栏），底色与菜单栏一致，行与行之间用空隙分隔、不画线。

内置脚本库

底栏「脚本」下拉收录 90 多个官方脚本，按分组目录组织，全部是纯文本处理，选中文本 → 点脚本 → 结果替换选区：

分组典型脚本
序号 / 配对加 1. 2. 3. 序号、去序号、括号引号配对、编号重排
转换正则替换、全半角、繁简辅助、大小写、时间日期插入
行处理去重、排序、去空行、合并行、拆行、列对齐
格式化中英混排自动加空格、缩进整理、Markdown 表格辅助

想扩充官方库：菜单底部「打开脚本文件夹」直达 script\， 把文件放进去，下次扫描即出现在菜单（同名内置脚本升级时会被官方版覆盖，自己的脚本请起不同名）。

自己写脚本

任何 .lua 丢进 script\ 就能用；文件头几行注释即元信息：

--!param mode=d,下拉|去重|排序  目标=select?
local out = rex.gsub(input, "\\s+", " ")   -- input 是选中文本
return out                                  -- 返回值替换选区
  • --!param 声明参数，运行前自动弹参数框（下拉/复选/文本，支持多语言名）。
  • API 四张表：editor（选区/光标）、win（弹框/剪贴板）、rex（PCRE2 正则）、pecia（宿主操作：开文件/保存/大纲/查找……）。
  • 完整手册就在随包 script\lua_api.txt——它同时是给人读的，也是给 AI 读的。
脚本拥有你账户的完整权限（文件读写、执行外部程序都在能力范围内），这是刻意的取舍——只运行你信任的脚本。

★ 让 AI 通过 MCP 帮你干活（复制这段话就能开始）

你不需要懂 MCP 协议，也不用记工具名。把下面这段话发给任何支持 MCP 的 AI， 它会自己去读随包文档、连上 Pecia、按规矩把活干完，并且自己验证结果。

可直接复制发给 AI 的话 
我有一个 Pecia 编辑器，安装目录在 <Pecia.exe 所在文件夹>，它是 Windows 上的轻量 Markdown 编辑器，可以通过 MCP 让你读写当前文档、运行内置 Lua 脚本、查大纲和设置。

请先打开安装目录，仔细阅读这些文档，并严格遵守里面的约定：
- docs\使用说明.zh-CN.html（整体功能）
- docs\MCP接入.md（怎么把你接到 Pecia 的 MCP 上，含配置原文）
- script\lua_api.txt（Lua 与宿主操作 API 全文，跑脚本前必读）

接好之后，先告诉我你看到了哪些工具、准备怎么做，等我确认再动手。

我要干的事是：<用大白话描述，越具体越好，比如「把当前文档里的引用编号重排，并检查有没有孤立的参考文献条目」>。

另外请遵守：改动优先走 doc.apply_edit（锚点不唯一它会拒绝，别绕过去硬改）；复杂变换写成 Lua 脚本，先 lua.validate（只编译不执行，会回行号和 Lua 原话），通过后 lua.run 跑起来看结果；已经装在 script\ 里的脚本用 script.run 加参数直接跑，不要弹窗；每步写完先 doc.get_text 复验再继续；需要脚本按某个输入运行时，把参数放进 script.run 的 params（不要依赖弹窗等人点，模态框会让 MCP 连接停在半路）；文档处于只读或仅预览时你会收到 perm_denied，这说明是被保护，不要重试，先问我。写入或运行失败的工具调用保证什么都没改，修好参数再调即可。
红色标注的 <...> 就是需要你按自己情况改的地方：安装目录填一次即可长期复用； 需求换成你真正想干的。其余文字原样发给 AI 即可。AI 连上后如果先问你问题，这很正常——它在确认需求边界。

这段话为什么这么写

  • 写明文档位置和「先读后动」，AI 就不会凭想象拼 API，也不会把简单替换拆成十次调用。
  • 要求它先报计划再动手，你可以在它改文件之前纠偏。
  • 把 perm_denied 的语义提前讲清：那是编辑锁在保护你的文档，不是故障。
  • 要求它自己复验，「改 → 读回 → 再改」的闭环不用你盯着。

接入的具体配置在 docs\MCP接入.md；接入后能做什么、边界在哪，看下一节。

AI 接入能做什么

Pecia 自带一个标准 MCP stdio 端点（Pecia.exe --mcp-stdio）， 不绑定任何特定 AI 客户端。任何支持 MCP stdio 的客户端，只要能配 command 和 args 两个字段就能接入。

  • 读：当前文档全文/区间、状态（路径/dirty/编码）、大纲、查找命中、脚本清单。
  • 写：锚点定位替换、全量替换、保存、开文件、切标签——全部只作用于当前标签，且遵守编辑锁。
  • 执行：lua.validate 只编译不执行，lua.run 把脚本跑在文档快照上 （出错即什么都没改，成功一次撤销回退），script.run 直接跑已装脚本并传参数； PCRE2 正则（rex.*）与宿主操作（pecia.*）全可用。
  • 界面量测：脚本弹出的界面（参数框、输入框、选择框）由宿主自己创建， 控件树也就由宿主发布——ui.inspect 读层级、ui.send 合成点击与输入、 ui.pixel 离屏取色、ui.wait 等界面出现或消失。 FLTK 是自绘控件，外部无障碍工具看不到这些层级，所以只能这么办； 这组能力主要给 Pecia 的自动化门禁做界面回归用。
  • 草稿落地：Lua 已经没有控制台窗口（m037）——草稿是一份数据，console.set 写入、console.get 读回；想亲眼看一下就让 console.show 把它开成一个普通编辑器标签， 确认没问题后 script.save 落成脚本文件，出现在底栏脚本条里。
  • 工具清单、lua_api.txt、pecia.ops() 三者同源——AI 看到的就是真正能跑的。
失败的工具结果保证「什么都没改」（isError），修正参数重调即可；客户端断开后 Pecia 窗口照常可用。

不想接 MCP 也可以用内置的 视图 > AI 对话面板（独立一栏，可与预览同时开着）：选中文字后走右键 发送到 AI，它会作为一条你的消息进对话；面板只有 清除 与 发送 两个按钮， API 地址/模型/密钥在 设置 > 选项 里填。回复要回文档就选中它复制——想要"改完自动写回文档"，那是 MCP 的活。

常见问题

打开几百 MB 的文件卡？

超大文档首次解析有可见停顿（已知设计），完成后会以只读方式打开——在提示里选完整编辑即可。

预览里公式 / mermaid 没渲染？

首次使用惰性加载，稍等片刻；仍不行用 菜单 > 刷新（Ctrl+R）强制重建。

远程图片显示不出来？

预览需要先联网取图并缓存；离线时显示占位。导出 HTML 时图片会一并本地化到产物目录。

设置存在哪里？换电脑怎么迁移？

全部在 exe 同级 settings.ini（含最近文件、分栏比例、快捷键），拷走它即是完整迁移。

多开几个 Pecia 会互相抢配置吗？

不会。配置多实例共享并实时同步；AI 对话是主窗口里的一栏，不会有各自的子进程，也就没有"谁抢谁"的问题。Lua 侧连窗口都没有了（m037）：脚本入口是底栏脚本条， 草稿是存在 script.last.txt 里的一份文本，运行结果看状态行。

能离线用吗？

能。编辑、预览、脚本、MCP 全不联网；只有检查更新和远程图片需要网络。
